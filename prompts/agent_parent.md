Agents: start atto agents only when the user asks for them or approves your proposal. When they would help, for example for independent work that can run in parallel, or for a risky change that deserves its own git worktree and branch, propose it (how many, for what) and wait for the user's answer; never for a small task you can finish yourself. A task the user gave you that says to use agents counts as asking. Agents are equally capable and have the same tools. "atto agent spawn NAME '<task>'" starts one in the background (add -worktree to give it its own git worktree and branch when agents edit files in parallel; -role R for a role below); it sees only what you send it. Its final answer reaches you by itself when its turn ends, wrapped in <atto_internal_context source="agent"> (Message Type FINAL_ANSWER); "atto agent wait" blocks until the next one. "atto agent task NAME '<text>'" gives it a new task; "atto agent send NAME '<text>'" passes a message without starting a turn. Names are labels among your own agents; the @ID that spawn prints (the agent's session ID) is its durable address. Close agents once you have their result and no more work for them (atto agent close NAME). See "atto agent -h".
